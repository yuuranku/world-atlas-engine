# 1.2.0：生成计算提速与两极独立设置

这次优化的是生成计算，不以降低分辨率、缩短政治迭代或删掉地理约束换速度。玩家认可的 B 世界网页保持原样。

## 实测范围

Windows / Python 3.14 / NumPy 2.3.5 / SciPy 1.17.1，B 世界原生网格 2176×1088。局部对照均在相同输入上运行发布的 1.1.0 函数和新函数，逐项断言数组一致。

| 计算 | 原实现 | 新实现 | 结果 |
| --- | ---: | ---: | --- |
| 陆地连通区域识别 | 0.751 秒 | 0.019 秒 | 标签、编号和面积一致 |
| 58 格距离覆盖 | 0.570 秒 | 0.024 秒 | 逐格一致 |
| 9,922 个控制区域的国界调整 | 69.133 秒 | 0.669 秒 | 全部区域归属一致 |

新版完整人文链路独立重算耗时 **259.176 秒**。数组语义摘要及完整实体 JSON 与保存的 B 世界相同，包含城市、交通、文化、宗教、国家、省份与命名。路由缓存复用 3,428 次，仅计算 1,314 条实际路径。

此时间不含先前已保存的物理网格生成、网页渲染、安装或人工看图。没有可直接相比的受控旧版整链路计时，所以不宣称“整个世界加速 100 倍”。数字也不是跨机器或任意种子的时长保证。

## 为什么加速

- 城市选择采用保持排序与精确距离的空间桶，避免候选逐一对比所有城市。
- 连通标记和距离覆盖使用 SciPy 的原生实现，保留经度环绕和有限纬度边界。
- 路径按完整代价场、通行域和有向端点缓存，代价变化即失效。
- 国界调整原本对大量无邻国、无有益交换的内部区域也扫描全国连通性。新版先筛选实际交换，维护实时成员集合，仍对每次转移做完整连通性检查。
- `timing.json` 累计物理、人文和渲染阶段的工作时间；中断续跑不再只记录最后一小段。续跑检查引擎版本。

复测工具：`tools/profile_generation.py`、`tools/benchmark_spatial.py`、`tools/benchmark_state_boundaries.py`。后两者直接从 Git 标签读取原算法，不在引擎内保留旧实现。

## 两极设置与验证

问卷从 15 题增加到 17 题，开头分别问北极、南极是否有大陆，支持独立随机并记录实际布尔值。配方字段分别为 `north_polar_continent`、`south_polar_continent`。

它们进入地壳潜势和海平面计算，陆地、海洋和海冰保持区分。四种组合均完成 144×72 端到端地形及物理字段验证；面积加权陆地比例为 34.992%–35.006%，目标 35%。小尺寸验证确认功能接通，不代替新世界的全尺寸地理、美术验收。

覆盖极点的大陆在经纬度展开投影中会横跨所有经度；普通大陆继续将左右接缝置于海洋。

历史 v38 和 v5 输入仍与 1.1.0 绑定。1.2.0 不猜测旧配方缺失的极地选择，不改写历史指纹；分发当前配方、世界设置样例和新轻量 skill。完整测试覆盖问卷、极地、空间精确性、国界决策、计时、安装、下载与渲染。
