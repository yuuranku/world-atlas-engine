# 区划形成与连续河道

dev20 的绘制共边修复没有解决形成层的问题：社会流水线末尾和绘制入口都再次从首府竞速，覆盖了原先的自然控制单元、机构强度和历史制度结果。等权、单源、四邻接的竞速不能代替国家形成，也会丢掉道路的对角通行能力。

dev21 删除这两条覆盖路径。普通生成和保存世界恢复共用城市腹地、自然地理单元、文化域、机构相对实力、时代响应时间和实际道路/航线构成的控制图。现有地方机关是国家控制的真实根；省份在所属国的地形和通行图内形成。保存恢复不重选首府、不重命名或删除国家与省份；旧跨文明父国由实际通行联系纠正，统计随归属重算。绘制只读取已形成的省份数组，国界由同一省份覆盖按父国合并。

现实行政边界可以依山脊、分水岭、河流，也可能继承历史制度或穿过自然单元。省份还受治理中心、交通联系与响应时间影响，因此不把每条大河强制变成国界，也不把每个流域直接命名成省份。共边圆化继续使用已有制图约束；它不负责决定哪个地区属于哪个国家。

河流的另一问题出在 D8 源图：长轴向和对角链由栅格流向产生，某些 Priority-Flood 平台在连续真实地面中甚至向下游升高。只圆化折角不能修复它们。dev21 从逻辑 reach 提取共享端点，在连续基准地形的横断面寻找低谷，用受河网间距限制的曲率求解得到一份连续河道。随后求共享的非增河床剖面，制图河流与局部谷地切深使用同一份 course/bed。桥梁从原生流路站位映射到这份河道，并共同求两岸门户。

这里没有重新实现 D-Infinity 流向，也没有任意添加正弦曲线。没有横断面低谷依据的直段仍可能保持直线。原生流向、水系、陆海分类及存档数组保持不变；细地形在明确河床支持范围内允许切深，原生中心精确高程合同相应更新。旧等高线绑定失效，在新目录重新提取一次，不能把旧 checkpoint 改标签继续使用。制图仍按四倍采样发现分支，并在同一个连续场上求根；旧区间认证器明确拒绝非空的新河床模型。

源城市格心是粗尺度地址，不是固定的真实城址。港口先在原城市附近的所属国范围或相邻海岸残片内选择真实岸线和可用陆地，再确定展示城址与码头；源地址保持不变。城市至码头的陆路复用已有多边形导航，必须在同一片干岸的局部连通域内，不以跨河或绕远处河源充当短入口。沿岸城址检查实际地形坡度。

原生路线格走廊根据附近源河段与展示河段的实测位移、实际河道半宽，加上四分之一格的岸形容许量构造，再与真实陆地相交，避免格边把同岸通路裁断。实际河道继续从通行区域排除，只有原路线的明确桥梁门户允许跨河；不因此增加桥或放宽水面检查。原城市干岸有合法港址时优先保留该岸和已授权路网。

当前共享河道的独立连续审计覆盖 822 条河段：河床上坡步数为 0，上坡河段、内部湿区河段和站点河床误差列表为空。最大建模下切为 **2287.84 米**，这是明显的地貌模型限制；保留原生网格和数组，不代表保留原始连续地表的全部高程。7 处源几何交叉使用共同交点的河床高度耦合，逻辑流路没有因此增加连接。该处理不等于恢复真实汇流水文拓扑，不能把几何 X 交叉称为已修复的自然汇流。没有足够低谷或曲线支撑的短直段继续保留。

最终冻结河道的缓存坐标测量绑定摘要 `ea250b2aa754fd1aa30b70ff4c4b94674d38e6f5c1616d9e73e52a4c984e1d24`：连续直段长度至少 5 原生单位的有 **2 段**，轴向及 45° 方向的长度占比为 **1.56%**（角度容差 `1e-6` 弧度）。原生单位不是公里，这些线形指标不保证现实地图品质；自然性依据仍是地形谷底和共享河床约束。记录为 `D:/2/world-line-quality/river-course-frozen-geometry-metrics.json`，不引用中间失败审计的数值，也不把未经绘制的原生 D8 源线当作旧地图的展示结果。

所有聚落的展示位置也使用同一连续地表：在原地址网格内选择真实干地，保持源河段与展示河段的岸侧关系，再交给港口和道路处理。当前世界 813 个地址全部通过干地与原格检查，7 个展示锚点细化，28 个具有明确岸侧的河段约束通过；没有原地址中心恰在河上或真实汇流端点的案例。因此这些专项结果不证明尚未遇到的多岸歧义已被全面覆盖。

专项港口审计覆盖 232 个港口，检查码头入口路线留在实际干岸、泊位不落在陆地上且连续场高程为负，错误列表为空。城市地面审计耗时 5.143 秒，港口专项耗时 29.276 秒；这两项是开发期间的独立阶段记录，不是最终整图生成耗时。最终独立交通结果必须以成功状态的实际记录为准，单凭港口或城市专项通过不能声称完整交通已经通过。

水面检查先对实际绘制链分别求交集，再合并真正的水面片段；整张路网的合并仍服务于拓扑。此顺序避免 GEOS 在近岸合并节点时制造差集误报，不改变道路、桥梁权限或误差容许值。

桥位先使用最近的连续河道投影。若河口投影没有两岸可用干地，则只在同一河段与既有许可道路的实际交点中选择仍受原桥格物理范围支持的站位；不选择孤立沙嘴、不建立新的渡河事件。桥头和该许可道路的岸段必须真实连通。本次道路 0502、0865、0866 共用的失败桥位实际位于入海口；代码同时处理入海与入湖河口。

山路求解先由栅格图搜索，再用真实连续场逐边验收；将栅格估算漏判的超限边从当前搜索图排除后继续求解，维持原坡度上限。当前保存世界的一段失败路径在此修复后由 10.633% 降到 8.635% 的真实峰值，保持全程干地；这项局部结果不代表所有种子都有可行山路。

桥跨的道路高程来自两岸支承点形成的桥面剖面，寻路、简化和最终坡度检查共用这一工程表面；桥外仍查询真实连续地形。当前世界 680 座原许可桥完成绑定，7 个曾按桥下河床误判的短段在桥面上全部通过，峰值 7.988%，标准仍为 10%。此处理不新增水面通行许可。

固定方向格点图无法到达弯曲岸线端点时，局部连接使用真实边界角点，并验证连续坡度和干地覆盖；不移动端点或提高整幅网格密度。当前最后一个失败链由此得到 168 点路线，完整链峰值坡度 8.442%，干地范围外长度为零。

河岸导航删除了一层极小 GEOS 缓冲。该运算在复杂河道上会将坐标降至约 8 位小数，使部分道路偏入水面；导航现在直接使用真实干地差集。保存世界的 22 个问题链对应 19 条道路，定向回算后未许可水面长度为零，未使用 ULP 豁免；未提高通行许可或误差预算。
