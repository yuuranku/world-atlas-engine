# 精确地图分块提速

地图仍使用原始连续地表、全部等高线顶点、精确海陆裁切及八位小数坐标。改变的是分块尺度和重复工作，不是物理计算分辨率或地形细节。

## 实现

- 主地图统一使用 32 个原生地图单位的分块。2176 × 1088 的地图由 27,744 个基础 JSON 文件减少到 6,936 个，三个原有缩放层级保持不变。
- 每个空间块同时完成三个缩放层级。精确几何交集、坐标编码和相同主题面组的合并结果各计算一次；海岸的不同显示几何及每个层级的 SVG ID 仍独立生成。
- 大地图默认最多使用四个 spawn 工作进程。输入和空间索引仅在工作进程启动时传入，各任务只接收连续空间块的索引范围。排队任务有界，交集和编码缓存只保留当前空间块，文件由拥有该空间块的进程写入。
- 工作进程异常直接终止这次分块阶段，未完成阶段不写成功 manifest；不替换几何，也不重跑全部世界。
- 写入器和独立检查脚本引用同一个 3 MiB 单块预算。前端和城市地形叠加层均从 manifest 读取分块尺寸。

32 单位的块在高缩放时会载入更大的一片几何；相应地，文件数、请求数、重复裁切和块边缘重复线段减少。旧成品中四个相邻 16 单位块的最大原始字节合计为 2,320,888，包含重复的裁切定义和边缘线段；因此仍使用 2 MiB 预算会对最密集区域造成不必要的阻塞。新预算为 3 MiB，而不是取消预算。

## 有界实际数据对照

使用莫恩凯尔现有 `land-potential.svg` 与已保存的 22 个精确高度层图；没有重新生成地形、河流、城市或国家。截取原生范围 `[1408,128,768,768]`，包含 1,129,626 个等高线顶点、45,233 个陆地轮廓顶点及 1,032 个源几何对象。解码和输入准备不计入下面的分块时间。

| 写入方式 | 分块尺寸 | 基础文件数 | 实测耗时 |
| --- | ---: | ---: | ---: |
| 原实现，串行 | 16 | 6,912 | 13.012 秒 |
| 原实现，串行 | 32 | 1,728 | 8.802 秒 |
| 优化实现，串行 | 32 | 1,728 | 4.525 秒 |
| 优化实现，4 个进程 | 32 | 1,728 | 3.775 秒 |

此样本从旧 16 单位串行分块到新 32 单位并行分块提速约 3.45 倍。32 单位样本每个块最大 828,442 字节，总计 80,709,885 字节。优化后的串行和并行文件均与原实现相同尺寸的输出逐字节一致，包括 SVG ID、裁切和 manifest 统计。进程启动计入时间，小样本会受到启动开销影响。

对照入口：

```powershell
python tools/benchmark_cartographic_tiles.py <已有世界的review> <全新结果目录> `
  --reference-ref <优化前提交> --region 1408 128 768 768 `
  --contours <已有世界的physical-contours> --workers 4 --tile-size 32
```

证据保存在本次任务的 `D:/2/tile-speed-benchmark-03/benchmark.json`（16 单位）和 `D:/2/tile-speed-benchmark-04/benchmark.json`（32 单位）。这个样本含一个主题及真实物理等高线，不是全部十三个主题，也不是完整世界的总生成耗时。不能直接据此宣称完整世界已达到十几分钟。

相关检查包括精确跨块河流和主题面、并行文件一致性、局部 SVG ID/纹理引用、3 MiB UTF-8 预算、工作进程失败传播，以及城市地形叠加层与分块检查器。
