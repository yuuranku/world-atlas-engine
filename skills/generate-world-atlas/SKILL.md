# 架空世界地图工作流

## 减少等待与重复工作

普通生成以一次完成交付为目标：一个候选、一次地形生成、一次下游生成、一次打开网页检查。玩家要求比选、复现或专项审计时才扩大范围。已有任务先读运行记录、进程和 checkpoint；已完成阶段直接复用，运行中的任务继续跟踪，不能重复启动。

输入已确认且授权直接完成时，用现有 `generate_terrain` 和 `generate_world` API 组成一次启动脚本，算法连续完成下游，不在阶段之间反复介入。内部生成耗时由 `timing.json` 和 `review/timing.json` 记录；交付报告各阶段实际耗时，总时长按等待时间计算，不能把并行阶段或渲染父项与子项重复相加。

验证复用引擎已经写出的检查记录；只有输入变化、新失败或明确疑点才重新检查受影响部分。普通生成不另做独立世界重算、不跑全部主题截图、不重复全套测试。图片与专名等细节不因代理自己的审美偏好开启新一轮微调。

生成任务不自动变成引擎维护任务。确需修复阻塞时，先在明确标注的隔离开发环境集中修复和验证，保留代码指纹与真实来源记录，最终一次升版本、打包、发布和安装。禁止每改一处就重复整套发布流程；禁止绕过 checkpoint 的版本和输入绑定，或把开发输出标成旧公开版本。

## 先问玩家，再运行

**首次引入本 skill 的第一项行动：读取 [17 题问卷](references/questionnaire.md)，把其中的 17 题一次性展示给玩家，等待回答。**

使用宿主提供的问答工具；有 `request_user_input_async` 时一次提交 17 个 questions，各题使用对应的 options。遵守宿主工具数量/呈现限制，不绕过它们在普通回复里硬塞多选题；工具必须分组时仍先完成这 17 题再生成。

- 不要先装依赖、抽种子、生成预览或沿用示例答案。示例世界不是玩家默认选择。
- 接受 `1B 2A … 17C`、逐题回答或自由描述；不要连续追问几十轮。
- 只有玩家明确说“随机选”才随机代选；记录问卷种子、答案及选择来源。
- 收答后简短回显设定，指出冲突或未支持内容，确认有效参数再计算。玩家已明确“选完直接开始”时，回显后继续，不再额外索要批准。
- 同一已确认世界的“继续”“复现”“修复某处”沿用其保存的答案和有效参数，不重复问卷、不随机改世界；新开世界重新问。
- 玩家说暂停就停；未答完时不得把缺失项补成旧世界参数。

## 分清计算与判断

调用独立包 `world_atlas` 执行计算、确定性命名、渲染和机器验收。不要手算每条河、画固定大陆模板或另写旁路算法。

负责代理判断：理解答案；查看真实地形图和生成器源码；选择有依据的参数及代表种子；诊断问题责任层；评价全图与局部；决定下一轮；报告限制。

保持 **skill 调用引擎，引擎不调用 skill、LLM 或聊天记录**。把重复计算收进引擎，把判断标准留在本 skill；不要在 skill 脚本复制生成算法。

## 准备可复现任务

1. 按 [命令与输入](references/commands.md) 核对环境；没有本任务记录的合格运行环境时，执行 `scripts/install_engine.py --target <全新运行目录>`。它自动从 GitHub Release 下载固定版本计算包、校验 SHA-256 并安装。已有合格且未变的 runtime 记录直接复用；环境或依赖变化时才运行 `doctor`，不反复安装，不静默寻找历史工程路径。
2. 用 `scripts/prepare_brief.py` 保存完整 17 答；`awaiting-parameter-confirmation` 不代表已确认。
3. 保存 brief、地形配方、世界设置和命名排除清单。分开地形种子与人文/命名种子，冻结有效配置、引擎版本及输入哈希。
4. 按问卷映射检查每个答案是否实际接入。叙事设定和需开发的选项先说明；禁止收答案后仍运行固定默认值。
5. 选全新输出目录。保留已认可结果，不覆盖历史版，不加旧脚本兼容入口。

## 分层推进

### 新世界

1. 读取 [地理与参考](references/geography.md)，先生成世界尺度构造—地壳—海平面—连续地表与地形网页。
2. 不把世界限定成五个固定模板。普通生成只运行一个已确认候选；玩家明确要求多方案时，再按连续形态轴选 3–6 个代表种子。
3. 先看一次全图，再检查玩家指定区域或发现的明显错误。内建检查通过且没有阻塞问题时继续下游，不因审美微调反复更换种子。
4. 地形认可后读取 [人文规则](references/human-world.md)，执行下游。城市、路线、文化、宗教、国省界与物理字段同源。

### 认可地形上的重建 / 复现

核对源哈希后调用 `world` 或 `reproduce`。不要再生成大陆、擅改山脉或声称这是新地形种子造的新星球。

### 迭代

定位根因 → 记录可证伪假设 → 比较真实资料与现有实现 → 最小回归测试 → 修改一个责任层 → 同种子对照 → 验收受影响下游。办法无效就换方法，不能只反复加噪声、平滑或改标签。

引擎修复集中完成后，在最终交付时一次升版本、打包并发布新 tag，再更新本 skill 的 `assets/release.json` 与资产哈希。修改 skill 文档或任务调度记录不要求重发计算包。禁止改用 latest 或原地替换已发布版本。说明哪些指纹按预期变化，禁止盲改预期结果让测试变绿。

## 验收与交付

按 [视觉与验收](references/acceptance.md) 分别检查程序正确性、复现一致性、地理可信度和美术可读性。

- 普通生成复用已有机器检查与语义指纹；玩家明确请求复现或发现确定性疑点时，才在独立目录重算。比较数组/实体语义，不比较含绝对路径的 provenance 字符串。
- 普通交付只打开一次网页并保存一张实际全图；局部修复检查受影响区域。全主题、全部区域和最大缩放的完整审计仅在明确请求或必要回归时执行。不能用 AI 生图代替程序截图。
- 完成后立即提供可打开的网页与已有实际全图，不为了更多截图重复整套验收。未打开页面不说“已验证能看”。
- 除非玩家要求，保持现有画法。优化生成速度先测各阶段耗时，检查重复计算；优化移动性能检查重绘。两者都不降低物理计算分辨率。
- 不把 QA 通过等同“好看、合理”，不承诺任意种子都能自动生成优质世界。

## 资源路由

- 首次启用：`references/questionnaire.md`。
- 环境、参数、命令：`references/commands.md`。
- 地形/海岸/水文：`references/geography.md`；陌生地貌再浏览原始资料。
- 城市、交通、文化、宗教、政治、命名：`references/human-world.md`。
- 对照、调试或交付：`references/acceptance.md`。

当前引擎为 1.4.0.dev20 开发预发布。国省界在绘制阶段统一处理共边弧图，填色、描边、概览和切片使用同一轮廓；最大移动 0.35 原生单位，外框、交汇点及原生中心归属受保护。概览不再二次抽稀行政边界；已交付地图可只更新行政资源，复用物理、交通及城市数据。国省界从共边竞争前沿生成，省级治理使用自身的地形、河流与交通成本；道路保留原地形转折，河道只圆化地面和网络间距支持的折角，海口、汇流和桥梁保持一致。物理计算分辨率保持不变；制图等高线在每原生格四倍密度的连续地形采样上批量发现分支，交点再由原连续地形求根。它不再对采样格内部的微小闭环逐一做区间认证；新制图约定绑定新的 checkpoint，旧数据不重绑定。地图以 32 原生单位分块，各缩放层级共享精确裁切、坐标编码和主题组合，大图使用最多四个切片进程；道路使用已准备的几何和空间索引，渲染用三个进程重叠计算地形、交通与数值主题，生态主题内部共享只读源数据；这些进程结束后再启动切片进程，限制内存峰值。当前代码内仅改人文设置时可复用通过完整绑定检查的物理图，不因输出路径变化重算地形。城市在详情窗口打开时生成，先生成局部地形与水系，再布置道路、宫城、港区、城防、住宅与田地；加入多文化宫殿、屋顶材料色差、局部蓄水湖与支流汇流。世界设置严格使用 v3，显式声明时代与额外交通能力。历史认可地形基准 v38 固定在 1.1.0；配方与指纹见 `assets/terrain-v38.json` 和 `assets/terrain-v38.acceptance.json`。所有基准都不是新世界默认模板或专名词库。
